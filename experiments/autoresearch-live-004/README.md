# AUTORESEARCH-LIVE-004 — inherit A, search for confirmed B

AUTORESEARCH-LIVE-003 earned one bounded result: a real external researcher produced a `train.py` candidate A that cleared the receiver objective in discovery and again in a fresh fixed-seed confirmation, after which the exact candidate was promoted. LIVE-004 does not reopen that search.

LIVE-004 asks the next earned question: can a fresh experiment instance inherit the exact accepted A and then advance again to a separately confirmed B under the same receiver boundary?

The inherited state is not reconstructed from prose. Bootstrap requires the frozen LIVE-003 result manifest and a predecessor git bundle whose SHA256 matches that manifest. The bundle must materialize exact commit `20a0df6cc98778ffb53957d6b4fafccda3a4973e`, whose exact parent must be the LIVE-003 baseline commit `effe44963da4d8b81ecc9be1ba3f115ac3ef2dab`. The predecessor delta must be `train.py` only and every immutable upstream blob must still match the pinned Karpathy repository.

After exact A is checked out, LIVE-004 creates fresh receiver state and measures a new A baseline. The LIVE-003 confirmation score is evidence about the predecessor result; it is not reused as LIVE-004's comparison baseline.

## Search and confirmation

Prince remains the same self-declared Muse personal agent / Muse Spark 1.3 research generator. The experiment permits at most 12 researcher calls. Each proposed B must descend from the current receiver-accepted state and change exactly `train.py`.

As in LIVE-003, the first discovery ACCEPT is only an apparent B. It is not promoted. The exact candidate must clear one fresh receiver-owned confirmation with no code, threshold, or instruction change between the two measurements. A failed confirmation ends the experiment; the protocol does not search for a second apparent B.

## What a positive result earns

`CUMULATIVE_GOVERNED_OPTIMIZATION_PROMOTED` means:

1. exact confirmed A was imported into a fresh experiment instance and verified against frozen predecessor evidence;
2. A was the receiver's starting accepted state and received a fresh baseline measurement;
3. the same external research generator proposed a descendant B;
4. B cleared discovery and confirmation before promotion; and
5. the receiver advanced accepted state from A to exact B.

That establishes **cumulative governed optimization**: the accepted system improved, inherited that accepted state, and improved again.

It does **not** establish recursive improvement. A changed the training system being optimized; it did not improve the mechanism that generates later improvements. Recursive language remains reserved for a later experiment in which an accepted inherited change demonstrably improves the improvement-generating process itself.

## Budget

The scientific search ceiling remains 12 researcher calls, 12 discovery evaluations, one confirmation, and one fresh inherited-A baseline: at most 14 receiver measurements / 4,200 seconds of training budget.

The outer resource ceilings are 150 minutes of pod wall time and $4.00 paid GPU spend. At the previously observed $1.60/hour, 150 minutes projects to exactly $4.00. The actual hourly rate must be recorded before bootstrap, and available account credit must cover the full projected wall-time ceiling. Setup, inheritance transport/verification, environment preparation, researcher handoffs, baseline, discovery, confirmation, and bookkeeping all consume the wall/spend budget.

Because upstream still fixes seed 42, the confirmation is an operational repeat under the same fixed-seed protocol. It is not an independent-seed statistical replication.
