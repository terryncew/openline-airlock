# RIL-RANK-LIVE-002 — GPU-metered Prince contact for the frozen ranking signal

RIL-RANK-EXEC-001 established controlled executable transfer of the exact frozen evidence-derived ordering. RIL-RANK-LIVE-001 then attempted the live contact test with Prince / Muse Spark 1.3, but it froze after session 1 because the preregistration demanded historical per-session Muse dollar telemetry that the substrate does not expose. That failure is preserved; LIVE-002 does not reinterpret or resume it.

RIL-RANK-LIVE-002 asks the same narrow scientific question under a cost contract that is actually observable. Two fresh Prince / Muse Spark 1.3 sessions receive matched 16-task packets. Candidate IDs, descriptions, features, shared history, public task information, Muse identity, available tools, GPU contract, and limits are identical. The only visible packet difference is the presentation order of the same 12 candidates: exact frozen evidence ranker versus exact frozen baseline order.

Prince may select any four candidates from the full 12. The receiver logs the four selections and their presented positions, then independently executes those candidates in Prince's returned order. Prince may follow, ignore, or reconstruct the presentation order. If the inherited ordering signal disappears on contact, that is a valid null result.

The GPU capability is a matched researcher tool, not a receiver. Before packet generation, the operator freezes one RunPod GPU SKU and quoted hourly rate. That identical contract is embedded in both packets. Prince may use the GPU only on packet-visible material and independently obtained public tooling/data; the OpenLine repository, evaluator, hidden truth, candidate implementations, receiver map, and matched packet stay outside the GPU workspace. A missing GPU or changed rate/SKU is an environment stop, not permission to substitute.

The primary remains 16 paired tasks. The 12.5-point threshold is exactly **two additional receiver-confirmed successes** for the evidence-order arm, and PASS also requires fewer downstream receiver evaluations. Paired outcomes, selections, presentation positions, receiver evaluation counts, Muse session/decision counts, session wall time, GPU runtime, computed GPU spend, and inherited 768-evaluation learning cost are preserved separately.

The GPU spend ceiling is still **$2.56 total / $1.28 per arm**. Runtime is frozen from a more conservative **$1.20 per-arm target** at the quoted RunPod hourly rate, leaving $0.08 shutdown margin per arm. GPU spend is computed from frozen rate × observed runtime. Provider-reported spend is preserved when available but is not required. Muse remains an explicitly unallocated fixed subscription substrate; LIVE-002 makes no total-economic-cost claim and invents no per-session Muse dollar amount.

A positive result earns only **single-run live selection transfer under this GPU-capable Prince substrate**. It does not establish repeatability, live coding productivity, Level 4 recursive improvement, recursive self-improvement, production value, universal transfer, economic payback, or hostile-process isolation.
